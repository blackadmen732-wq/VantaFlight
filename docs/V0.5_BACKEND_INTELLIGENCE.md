# V0.5 Backend Intelligence

## Scope and safety

V0.5 adds simulation-first perception, racing, course generation, measurement,
and optimization foundations. It does not redesign the desktop application.

The control boundary is:

```
camera → VantaFrame → VantaDetect → VantaPose → VantaTrack
       → VantaFusion → VantaScene → VantaPredict → VantaRace
       → normalized trajectory/setpoints → PX4
```

PX4 remains responsible for stabilization, attitude control, and motor control.
VantaFlight does not generate raw motor PWM values. Autonomous racing is
simulation-only. The PX4 SITL adapter rejects serial links, remote hosts,
non-UDP transports, and UDP ports outside the configured SITL range before
MAVSDK connects.

## Coordinate frames

- Camera optical frame: right-handed OpenCV convention, `+x` right, `+y`
  down, `+z` forward through the lens.
- Aircraft body frame: front-right-down (FRD), `+x` forward, `+y` right,
  `+z` down.
- Local world frame: north-east-down (NED).

`CameraProfile` owns the calibrated camera-to-body transform. Aircraft state is
normalized before entering vision; the vision package does not import MAVSDK.

## Timing and stale-data policy

Frames retain capture and receive timing, while stage timing records
preprocessing, detection, pose, tracking, fusion, planning, and command times.
Prediction keeps the raw observation and produces a separate predicted-now
pose with horizon and uncertainty.

Camera queues are deliberately tiny. Consumers take the newest useful frame
and discard stale backlog. Analysis recording also uses a bounded queue and
batch writes off the perception/control path. Raw video is stored as external
files with metadata references, never as SQLite blobs.

## Simulator truth boundary

Simulator truth contains exact aircraft state, gate geometry, and timestamps.
It is available only to Digital Twin validation and VantaForge analysis.
VantaSight receives rendered camera frames and normalized aircraft state; it
must not receive gate truth as perception input.

## Deferred validation

Live PX4 SITL/Gazebo results must be recorded separately from unit and
synthetic-image tests. A passing deterministic synthetic test does not imply
real-camera, simulator, or hardware verification.

## Measured benchmark

Run the deterministic CPU benchmark from the repository root:

```bash
backend/.venv/bin/python scripts/benchmark_vision.py --frames 250 --burst 2 --json
```

It reports processed/dropped frames, effective FPS, median/P95/P99 end-to-end
latency, per-stage medians, pose error against synthetic ground truth, and
tracking continuity. Results describe only the machine and parameters printed
for that run; they are not a hardware-rate claim.
